## Epic H: authoring UO data files, owner's top priority (started 18:30, 2026-09-27)

Goal: walk around in game wearing Codex's **Dreadcrest** shield (candidate in
`build/uo_original_expansion/dreadcrest_wearable/`, handoff in `design/uo-original-expansion/`), and
give every GUO user a safe way to add art and animation to a shard's data files.

Principles: never write into the player's UO install. Work on a **staged data set** (a copy, per shard
project) that the client and the dev shard point at (this is Epic G's "custom data folder"). Find
**free slots** and keep each pack's new assets together in reserved **ranges**, recorded in a registry.
Every write is verified by decoding it back.

| # | Story | Owner | Done when |
|---|---|---|---|
| H1 | ADR-0022 "Authoring UO data files", plus `tools/uodata_write`: a staged data set (copy-on-write from the install); a free-slot scanner per namespace (land/static art, gumps, anim bodies and actions, tiledata items, hues); a range allocator with a registry (`slots.json`: pack → reserved ranges, ids used); container writers for MUL+IDX (art/artidx, gumpart/gumpidx, anim/animidx, tiledata, hues) and the LegacyMUL UOP forms (hash tables rebuilt), reusing phase 5's encoders; a verify pass that re-reads every written entry through the ported loaders | GUOeditor | ADR Proposed; unit + round-trip tests on a scratch copy; the install untouched (checked) |
