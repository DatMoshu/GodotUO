### S2. Six-button macro coverage (GUOUI, after S1)
From `docs/second-screen-ui-research.md`'s test matrix: desktop fixtures and TouchProbe assertions that
Next Target, Attack Last, Last Target, Last Object, Bandage Self and War/Peace each produce exactly the
intended action (a spawned mobile via `--shard-command`, bandages in the pack). Then one Thor pass.
Done when: the probe asserts all six, with log lines as evidence; any mismatch with upstream is written
up, not "fixed", unless GUO differs from ClassicUO.

### S3. Controller input on Android: Thor layout detection and basic dispatch (GUOAndroid), priority 1
Follow `docs/thor-controller-layout.md` steps 1–3 on the device: measure Standard / Xbox /
Disconnected, capture the Godot joypad events per physical button, and check what the exported app can
read. Then native gamepad dispatch in `GodotInput` (currently none) for the basics: d-pad or stick walks,
the confirm/cancel buttons act on the focused gump or target, and one button opens the macro row.
Resolve the layout (Standard/Xbox/Unknown, plus a manual choice in Options) before translating.
Done when: a table of measured values per mode; a Thor video or photos of walking and confirm/cancel by
controller; unknown layouts fall back to a manual setting, never a silent guess.

### S4. Steam Deck Game mode and controller (GUOAndroid, after S3's dispatch)

confirm/cancel, and a documented Steam Input template (as a file in `tools/steamdeck`). The Deck is on ssh.
Done when: a screenshot from Game mode; `docs/steamdeck.md` updated.

Done when: ADR-0014 Proposed; the headless editor_smoke gains a world-objects stage; export, restart,

### S7. Theme, sound and preset contracts (GUOeditor, moved from Codex; draft only)

### S10. Web client: what blocks it and how to unblock it (GUOWeb), added 10:50
The owner wants a deployable web client. Phase 1: research upstream's C#/.NET web export
(godotengine/godot#70796 and its linked branches), the .NET browser-wasm runtime, and GUO's own
blockers (TCP sockets need a WebSocket bridge, threads, file IO to the install, payload size). Write
`docs/web/unblock-report.md`: blockers ranked, how to unblock each, who acts, the effort, and a
recommended path. Phase 2 after the owner's go: build the most viable upstream branch in a gitignored
`tools/godot_web/`, prove a tiny C# project in headless Chromium, then GUO's login screen with client
data over HTTP, then the shard through a TCP↔WebSocket bridge. The pinned `tools/godot` is never touched.

### S11. Screensaver picker and screensaver packs (GUOAndroid; content by VideoMaker), added 11:15
An Options dropdown to choose the screensaver: the current drifting effects, three built-in loops, and any
installed screensaver packs. A new Asset Store kind `screensaver` (ADR-0019 amendment, validators,
tests). VideoMaker makes four OLED-safe loops. Three ship built in; one is published only to the store,
so testers can install it. Profile v11 with a migration test.

### S12. Hold-and-flick gumps (GUOUI), added 11:15
Hold a gump: it lifts (scale about 1.04, outline) and four direction chips appear. Flick up or down to move
it to the top or bottom screen, left to close (with undo), right to reset size. Each direction is
configurable in Options. Dragging across the screen boundary also moves a gump. Built on
GumpPresentation.

### S13. Backgrounds and splash (VideoMaker), added 11:15
Six more UO-inspired CC0 background loops, published as store packs. An in-engine boot splash: the
sigil fades in with a gentle scale, one light sweep, then a crossfade into login. About 2–2.5 s, skippable,
reduced-motion aware, with an Options toggle.
