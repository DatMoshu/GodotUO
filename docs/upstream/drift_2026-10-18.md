# Upstream drift, 2026-10-18: ClassicUO main and the 2.0 beta

Story UP-01. Assessed 2026-10-18 against the reviewed pin in
[UPSTREAM_PIN.json](UPSTREAM_PIN.json), `007ef8c3e1` (2026-09-08, "Read item
art and ground of our own from a folder"). No code changes; the pin does not
move in this change. It moves at the end of the upstream sync PR, after the
takes it needs (see the last section).

## Summary

- **ClassicUO `main` is 8 commits past the pin** (head `ee79d7ebc1`,
  2026-09-29). All 8 touch files GUO has already ported. Five are takes, three
  cancel each other out (net change: one comment).
- **The 2.0 beta has no public source.** It ships from ClassicUO's deploy
  repository (release entry `2.0.0.0`, beta, published 2026-10-17 and
  2026-10-18) as two binaries: a small .NET Framework 4.7.2 `ClassicUO.exe`
  host and a native `cuo.dll`. No branch, tag or pull request in
  `ClassicUO/ClassicUO` carries it: `beta` (`07f920904b`, 2026-04-25) is behind
  `main`, and the last public ECS work (`impl/ecs`, 2026-06-28) stops months
  before the release.
- **The 2.0 core is not C#.** The native library's own strings show a Rust
  build on wgpu with WGSL shaders, wasmtime as the mod host, and rodio for
  audio. The animated water and new terrain are a "liquid terrain pass" that
  samples Enhanced Client textures (two terrain textures blended by a noise
  mask, a wind-scrolled normal map for water), described in its comments as a
  twin of the EC's `LiquidTerrain.fx`. Modding is WebAssembly components
  against the public `ClassicUO/classicuo-mods-sdk` (WIT interfaces), with
  mods published in `ClassicUO/classicuo-mods`.
- **So nothing in the 2.0 beta is portable under GUO's model** (transplant
  ClassicUO's C#, AGENTS.md). Its renderer, mod host and EC asset path are
  ideas to learn from, not files to port. They go to the lanes that own those
  ideas (below), as design references only.

## How this was measured

- `git fetch` of the read-only reference under `sources/ClassicUO`; its
  checkout stays at the pin, so `tools/port_drift` keeps comparing against
  what was reviewed. `launchers\dev\sync_upstream.bat` without `--no-fetch`
  fast-forwards the checkout, which would move every lane's reference at
  once, so it was not used for this.
- `git log 007ef8c3e1..origin/main` with `--stat`, every upstream file mapped
  to its ported file under `godot/GUO/src`, and each GUO file checked for the
  change (none of the 8 is in GUO yet).
- `python tools/port_drift/run.py` on this branch: 298 identical, 99 marked,
  **0 unmarked**, 209 GUO-only. The port is clean against the pin, so every
  take below starts from a faithful file.
- The 2.0 beta: the deploy repository's manifest and history through the
  GitHub API, the two released binaries downloaded and read for strings only
  (never run). No upstream code from them is reproduced here or anywhere in
  the repository.

## What changes in GUO because of this report

Nothing yet. The takes become two PRs:

1. `ee79d7ebc1` (containers on a facet change), on its own. Its file,
   `Network/PacketHandlers.cs`, already carries marked deviations, so CI's
   `port_drift --strict` passes whichever pin is current.
2. One upstream sync PR with everything else, one upstream-authored commit
   per take and a GUO commit beside a take where GUO's code needs it:
   `7335535a11` (verdata animations), `5b30862872` (reload our assets),
   `266cdfcafa` and `75c7018bc3` (mounts), the comment `c2cfeaa72a` leaves
   in `ButtonTileArt.cs`, and last the pin bump to `ee79d7ebc1`.

They travel together because CI checks `port_drift --strict` against
upstream at the pin: a take merged before the pin moves is unmarked drift,
and a pin moved before its takes makes every file not yet taken unmarked
drift. Proofs in the sync PR: the Britain render dump unchanged by the
verdata take, a mounted-rider parity dump, and the reload button working.

The EC asset scope (UP-03) is a separate document, with no code.
