## What changed (PLAT-01)

- **Engine cache:** already in place. `release.yml` caches the pinned Godot and its
  mono export templates (~1.3 GB) by version in both build jobs. Nothing to add.
  `ci.yml` and `build.yml` do not run the engine.
- **NuGet cache, new:** every .NET job (CI `build` and `server-adapters`, build's
  `desktop` and `android`, release's `export` and `android`) restores
  `~/.nuget/packages` with `actions/cache`. The key is per workflow, job and
  matrix leg, plus a hash of every `*.csproj`, `*.props` and `*.targets`
  outside `sources/`. Jobs restore different package sets (the Android runtime
  packs, the pinned server APIs), so a shared key would let the first job to
  save leave the others with a partial cache. A changed project file falls
  back to the job's last cache through `restore-keys`.
- **Gradle cache, new:** release's `android` job caches `~/.gradle/caches` and
  `~/.gradle/wrapper`, keyed on the Godot version. The Godot Android build
  template's Gradle downloads depend only on the engine.

The saving can only be measured once this is on `main`. GitHub saves caches
per branch, and a PR can restore `main`'s caches but not another branch's.
The first run on `main` fills the cache, and the runs after it show the time saved.
The step to check is "Build the client" and the restore inside "Export Android".

## Next, if CI nears 10 minutes

1. **Run the pooled tests in parallel** (`pytest-xdist`, `-n auto`). This is the
   biggest saving available, since the step is 341 s of the 8.5 min. First check
   that tests sharing a `build/` subfolder or a fixed port (shard_content,
   agent_queue, asset_store's served folder) are isolated. That is a separate
   story, because a race brought in here would be a new flaky step.
2. **Drop the extra `setup-dotnet` SDKs** where the hosted image already has them
   (27–82 s per job). Check the image's preinstalled SDK list before removing any.
