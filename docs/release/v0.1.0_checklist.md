# v0.1.0 release checklist

For the owner. Cutting the release is the owner's alone: an agent prepares,
the owner tags and publishes. Tick each line on the day; a line that fails
stops the release until it is fixed or written into Known Issues.

The notes the draft release carries are `docs/release/v0.1.0.md`: the
`release` workflow attaches them when the tag is pushed.

## 1. Before the tag

- [ ] `main` is green: the latest `ci`, `build` and `release` runs on `main`
      succeeded (Actions tab).
- [ ] `launchers\dev\smoke.bat` ends with `OK` on a clean checkout of the
      commit to be tagged.
- [ ] `python tools\privacy_scan\run.py` is clean, with the private deny
      list loaded (it lives only on the owner's machine).
- [ ] `python tools\docs_lint\run.py` and
      `python tools\wiki_publish\run.py --check` report no issues.
- [ ] `CHANGELOG.md`: the `Unreleased` heading becomes
      `## 0.1.0 (YYYY-MM-DD)`, with a fresh empty `Unreleased` above it.
- [ ] `docs/release/v0.1.0.md` matches the changelog: what's in it, the
      downloads table and the main known issues.
- [ ] The README's Status section and the wiki's Home page say the same
      thing as the notes.

## 2. Known Issues is honest

- [ ] `docs/wiki/Known-Issues.md` has been re-checked against `main` (story
      UX-01): every entry still happens, and nothing found since is missing.
- [ ] Every entry says what the player sees and, where there is one, the
      workaround.
- [ ] The optional features are listed as optional: Enhanced HD, regional
      audio and recorded voices are off by default, and NPC speech is silent
      without a voice pack.
- [ ] Frame rate zoomed far out is named as behind ClassicUO.
- [ ] The release notes' Known issues paragraph links the page and repeats
      only its top entries.

## 3. Builds, from the release workflow

Push the tag from the commit checked above:

```
git tag -a v0.1.0 -m "GodotUO 0.1.0"
git push origin v0.1.0
```

The `release` workflow builds the three platforms and opens one **draft**
release with the notes file and three zips. Then:

- [ ] The draft has `GUO-windows-x86_64.zip`,
      `GUO-steamdeck-linux-x86_64.zip` and `GUO-android-arm64-debug.zip`.
- [ ] **Windows:** unzip on a clean Windows 10 or 11 machine, set
      `UO_CLIENT_DATA`, run `GUO.exe`: it reaches the login screen and logs
      in to a shard. The window icon is the GodotUO sigil.
- [ ] **Steam Deck:** `launchers\steamdeck\smoke.bat` with the zip's build,
      or copy it across and start it: it reaches the login screen.
- [ ] **Android:** install `GUO-debug.apk` over a previous build; it starts,
      finds the UO data and reaches the login screen.
      (`launchers\android\smoke.bat --avd guo_phone` checks the same on the
      emulator, but the release APK is arm64, so the emulator run uses its
      own x86_64 build.)
- [ ] None of the zips contains UO game data: list each one and look for
      `.mul`, `.uop` and `.idx` files.
- [ ] The draft is marked **pre-release**.

## 4. Wiki and site

- [ ] The `wiki` workflow ran after the last change to `docs/wiki/` and
      succeeded; the GitHub Wiki shows the new pages (Feature Layers,
      Content Packs, Admin Tab).
- [ ] The Roadmap's "Now" section is updated once the release is out.
- [ ] The project site (the `pages` workflow) links the release.

## 5. Publish (owner)

- [ ] Publish the draft release.
- [ ] Post the Discussions welcome below in **Announcements**, and pin it.
- [ ] Any other announcement is the owner's own, after the release is
      public.

## Discussions welcome post (draft, not posted)

> **Title:** GodotUO 0.1.0: the first preview
>
> GodotUO is Classic Ultima Online on Godot 4 .NET. It carries
> ClassicUO's network code, file readers and game logic across as they are,
> and rebuilds only the parts that were tied to the old engine: drawing,
> input and sound.
>
> 0.1.0 is the first preview you can download: Windows, Steam Deck and an
> Android debug build, from the Releases page. You need your own Ultima
> Online installation; nothing here contains game data.
>
> What to expect: it logs in, walks, trades, opens gumps and runs assistant
> plugins against a ModernUO shard, and it plays with a mouse, a gamepad or
> touch. It is not yet identical to ClassicUO everywhere; the Known Issues
> page in the wiki says where it differs. Extras such as HD art packs and
> recorded NPC voices are options, off until you turn them on.
>
> Where to start: the wiki's Getting Started page. If something looks
> different from ClassicUO in the same spot, a bug report with both
> pictures is the most useful thing you can send. Ideas go in the Ideas
> category; questions in Q&A.
>
> Thanks to ClassicUO, whose code this is built on, and to ModernUO, the
> shard behind every test.
