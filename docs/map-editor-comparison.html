Painting a UO map

World edits individual land cells and statics. MapGen generates a facet and verifies its MUL export. CentrED# lets several builders edit the same server-backed map. The biggest gap for a mapper moving to GUO is carrying familiar terrain choices and coast rules into an ordinary brush stroke.

Which brushes travel?

The upstream manager reads TilesBrush.xml from CentrED+. It maps hexadecimal land IDs and directional edge types to named brushes. Its converter ignores the base tile’s Chance attribute and maps unknown edge types to zero. Profiles store a land_brushes dictionary with Tiles and To. Legacy landbrush.json uses Transitions. On the GUO baseline, selecting a raw current dictionary silently drops its edges. This branch reads both spellings in the existing custom-table picker. Supply only the JSON value of land_brushes, with brush names that match GUO materials. A complete CentrED# profile is a line-oriented settings file. CED+ converter · profile migration · GUO reader

No direct Landscaper reader surfaced in the inspected upstream brush IO, tools or manager window. Similar edge picking does not establish file compatibility. GUO MapGen descends from the owner’s CentrED# fork and explicitly reads selected Landscaper catalogues. MapCreator’s author separately describes compatibility with Landscaper XML. Dragon compiler and variants

A Dragon map author paints an indexed BMP, edits the scripts for that palette, and runs Bitmap To Map. Dragon produces terrain MUL and writes item placements to SCP. DragonSP freezes selected SCP lists into a static index and data file. GUO’s prepare --dragon covers one part of that process. A successful table import alone cannot reproduce the source map. Ryandor’s mapping manual, appendix B · Repeat the native experiments

Which version does a map need?

The Imod9+ and Imod13 packages examined contain the same Dragon.exe (SHA-256 prefix 1ed203a6030f). Both identify themselves as 1.03.62 Beta. Their groups.txt maps a palette slot to a terrain group; maptrans.txt maps the slot to decimal base Z and a pool of hexadecimal tile IDs. Mod 10’s binary identifies itself as 1.05.00 prerelease #6 (34d45eaf50b4). Mod 11 uses prerelease #8a (75e22df82e1a). Their maptrans rows include slot, group, Z and tiles together. Mod 10 still includes a groups file. File presence does not establish which copy a reader uses. Prerelease #6 and #8a produced identical decoded land on the 32 × 24 reference. The 1.03.62 build rejected that BMP size. Running the same shoreline and height landmark in a 6144 × 4096 BMP produced a valid map with separate groups.txt and maptrans.txt inputs. The freezing experiment used the DragonSP 1.00.00 bundled with Mod 11. Pinned variant collection · Tested distribution

What GUO currently imports

Mod 11’s Scripts/Betweentrans.txt dispatches an ordered source/destination group pair to a named file. Other files declare same-group transitions, static transitions, uneven terrain and structures. The synthetic Dragon dispatch points to Map/trial.txt. Dragon compiled it; GUO refused the folder because its discovery requires a filename matching *2*.txt. On the unmodified Mod 11 package GUO parsed 22,864 rows from 96 files with zero syntax skips, produced 18 source brushes, and reported unfamiliar names including 2Cobble. It scans filenames independently of which files the native dispatch activates. The output therefore measures parsing coverage, not map parity. Discovery · Importer

GUO rotates Dragon’s clockwise NW-first mask into its N-first byte. Its brush selector finds minimal containing masks and offers tied tiles as variants. The #8a experiments showed a superset miss and a last-row winner. The 1.03.62 full-facet experiments gave the opposite duplicate-row precedence. An importer that collapses row order cannot reproduce both versions. GUO preserves decimal altitude bounds in the imported records; tile lookup returns only an ID. Separate World and MapGen scatter controls do not consume Dragon’s SCP freeze workflow. Priority order is dispatch and palette/Z decoding, then exact mask/order/height parity, then static groups and reproducibility. GUO lookup · Acceptance plan

Lineage and interoperability

  • Dragon variants. The 1.03.62 introductory form credits AwA’s original work and tables and describes its Windows C++ core. Identical executable hashes establish shared binaries for the sampled Imod9+ and Imod13 packages. The public archive supplies scripts and executables. Its file list did not reveal original compiler source. Separate evidence would be needed to identify the implementation ancestry of each binary. Versioned archive
  • UO Landscaper and norad32. The MapCreator author reports that Landscaper used Imod9 transitions. The norad32 package supplies Landscaper XML, including Mod9.xml and Mod11.xml mappings. This supports data lineage; direct Dragon compiler code ancestry remains unverified. Author’s account · XML mappings
  • MapCreator. Its author describes a C# port/reconstruction of UO Landscaper’s VB implementation. The tree includes a Dragon Mod 09 palette. A direct port of the Dragon executable has not been established. MapCreator source and author’s account
  • UOMapWeaver. It has separate MapTrans text and XML readers and identifies its code as original. That establishes format support without documenting a fork of Dragon. Pinned readers
  • CentrED#, GUO and UOFiddler. CentrED# directly imports CentrED+ XML. GUO’s MapGen descends from its author’s CentrED# fork and adds a Dragon script converter. UOFiddler provides MUL inspection. None of the inspected sources established a Dragon compiler port for these tools. Source and data register · GUO provenance

Original Dragon rules, binaries and artistic palettes have no verified redistribution grant here. The tests generate their own palette, pixels, filenames, rules and placements. Only the fixture generators and oracle belong in the project.

Hands-on checks

The 0.7.0.4 importer read a two-material synthetic CED+ XML. Edge type DL became northeast (mask 2), selecting tile 0x0035. The same importer rejected norad32’s Terrain.xml. The upstream profile converter wrote and reopened the dictionary; a GUO test checked that its northeast tile did not appear southwest. The test harness replaced the UI/profile store and used the upstream conversion and lookup code. The release GUI and multi-client session remain unverified.

World’s editor smoke opened the terrain picker, canceled, reopened it and confirmed a two-entry palette. Confirming an altitude document displayed the format error and left both swatches usable. Choosing tile 22 and then tile 3 through the popup retained size 11, density 35% and spacing 2. On facet 0 at (1498, 1629), the project reopened with land 0x0003 and Z 10. Undo restored the original block text.

The upstream writer’s Pier and Bay dictionary passed ingestion and export read-back for 8,192 cells and 1,998 statics. To test placement, two further 128 × 64 runs used recognized Grassland and Forest brushes, seed 528 and zero sliver passes to preserve the input corners. The only dictionary change was the direction of marker 0x3123. An independent check predicted corners from the baseline biome grid and decoded the exported MUL. The northeast dictionary painted all 14 northeast corners, including (60, 13) at Z 0. Switching the edge to northwest restored tile 3 there and painted all 14 northwest corners, including (67, 13) at Z 0. Neither map contained the marker elsewhere.

The separate 256 × 256 World reopen used 65,536 land cells and 13,721 statics.

Godot’s headless hot-reload check completed its first pass and failed to unload the assembly on both the painter slice and its integration control (45727cc6). The underlying cause remains open. A separate full smoke encountered a Windows access error while publishing a staged World folder. Export of the same run to a new destination passed. The World editor reopened all 1,024 blocks at (19, 37), Z −5.

What to build first

  1. Prevent silent changes to the terrain. Resolve a palette entry to its land tile, preserve Z, and reject unsupported formats before replacing the active selection.
  2. Make a coast reproducible. Carry the source pair and eight-direction orientation through preview, stroke, undo and reopen. Require fixtures for asymmetric shores and mixed corners.
  3. Carry a painted draft through export. Use the existing image-import pipeline and pass controls. Bind source images and palette identity to the result. Click a warning to inspect the corresponding World cell.
  4. Prove collaborative and large edits separately. A pair of editing clients must agree on the same saved block after a conflict and reconnect.
